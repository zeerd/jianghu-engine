# 游戏简报：「金剑江湖」服务端引擎（jianghu-engine）

**一句话定位：** 一个「写 Lua 就能开服」的武侠 MUD 服务端引擎——C++ 内核驱动网络、战斗、属性与持久化，全部游戏内容（NPC、物品、技能、房间、任务、状态、命令）由 Lua 脚本实现，自带一套示例世界即开即玩。

## 核心循环 — 内容作者/运营者的循环
- 改 Lua 数据集脚本（`npc` / `item` / `skill` / `room` / `condition` / `data` / `command` 分目录）→ 服务器热重载加载，`--check-lua` 先全量校验语法与绑定环境
- 跑质量闸门：引擎单测（`run-coverage.ps1`，Release 生产同构 + 覆盖率增量）与 CLI 无头剧本集成测试（`run-integration-tests.ps1`）
- 起服 + CLI 客户端（或任意 TCP 客户端）连 6600 实机体验
- 角色/房间/住宅自动落库（MySQL / SQLite 双后端），改内容再出发

## 目标与失败态 — “能用”长什么样
- **目标**：内容作者不改一行 C++，仅凭 Lua 数据集即可交付一个完整可玩的世界（注册 → 成长 → 战斗 → 经济 → 住宅 → 副本），可持久化、可回归测试。
- **失败态**：脚本错误拖垮核心进程；存档丢失/损坏；协议不兼容使客户端全灭；单进程性能撑不住在线量。（验收标准可追溯至此）

## MVP — 引擎成立的最短清单
1. TCP 文本协议（6600、GBK、XOR 混淆、`\t` 分隔、`&C=N&` 消息）+ 登录/会话/断线处理
2. Lua 5.5 引擎：分类型目录加载 + 热重载 + `--check-lua` 启动前校验
3. 核心对象体系（char / npc / item / room / condition）+ dbase 键值存取
4. 战斗管线（12 阶段：技能选择 → 闪避 → 格挡 → 伤害 → 武器特效）+ 22 个武器使用位 + 技能/魔法注册与继承，Lua hook 可改写伤害、击杀奖励与战斗规则
5. 成长系统：属性/等级（175 级经验表）/技能上限/师徒/打坐/读书
6. 持久化：MySQL/SQLite 双后端，角色/房间/住宅自动保存
7. 场景系统：金钱自动合并、商店、钱庄、住宅区、限时自毁副本实例、NPC AI

## 不做 — 刻意不做的
> `INTENT UNKNOWN` — 以下由代码缺失推断，未经作者确认（x64 除外，README 明示）
- x64 构建（README 明示暂不可用；当前仅 Win32）
- 图形客户端与美术管线——纯文本引擎，表现层归客户端/内容集
- 可视化编辑器 / 运营后台——管理走游戏内巫师命令
- 内置任务（quest）框架——刻意以 `hooks.pre_talk` 等钩子 + dbase 状态机实现，引擎不提供任务类型
- 跨服 / 分线架构——单进程单世界
- Lua 沙箱权限隔离——脚本与 C++ 绑定同权

## 构建顺序
1. Lua-C++ 绑定与对象体系（风险最高、所有系统依赖的接缝，含 hook 机制设计）
2. 网络层 + 协议 + 登录/会话
3. 战斗管线 + 技能/魔法机制（引擎的“好玩内核”，先证明它成立）
4. 持久化（dbase 落库、双后端）
5. 经济 / 住宅 / 副本 / 社交等场景系统
6. CLI 客户端 + 无头剧本集成测试 + 覆盖率门禁（质量闭环）
