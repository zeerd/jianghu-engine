## Summary

队伍轮换制的回合式文字战斗系统：战斗发生在一个按需创建的虚拟房间 `CFightRoom` 中，
两队每 2 秒交替行动，每次攻击走 12 阶段管线（技能选择 → 闪避 → 招架 → 伤害 → 武器特效），
命中与否由战力比骰（`dp/(ap+dp)`）决定，战力来自技能等级立方与战斗经验的加权 `[inferred — confirm]`。
所有数值规则的决策点都留有 Lua hook，C++ 只申报时机、规则归脚本
（`src\lua\CombatRules.h:3-5`）。

## 1. Overview

**Purpose**：为武侠文字世界提供「见招拆招」的战斗内核——玩家通过技能搭配、
内功加力、闪避/招架概率与队伍协作影响胜负，而非实时操作。

**Scope**：
- **在内**：战斗房间与队伍调度、攻击判定管线、伤害/负伤、忙碌与中断、
  毒/状态条件、魔法施放、击杀与 PK 结算、NPC 主动敌对 AI、昏迷/死亡/复活。
- **不在内**：技能本身的获取与练习（成长系统，见 `src/char/CharSkill.cpp`）、
  组队社交结构（`src/cmd/CmdUserParty.cpp`）、战斗外的聊天/经济。
  战斗数值的**内容**（招式表、动作文案、伤害修正）全部由 Lua 技能脚本提供。

**Current Implementation**：
- 调度：`CFightRoom`（`src\item\FightRoom.cpp`）——`cmd_hit_ob` 创建虚拟房间、
  双方搬入、`begin_fight`；`heart_beat` 每 2 拍推进（`tick < 1` 跳拍），
  `advance_ap()` 累积行动点后 `run_team_turn()` 执行当前队行动。
- 判定：`CAttack::execute`（`src\combat\Attack.cpp:25-66`）12 阶段管线。
- 战力：`CCombatCalc::skill_power`（`src\combat\CombatCalc.cpp:14-58`）。
- 结算：`CReward`（`src\combat\CReward.cpp`）；敌对 AI：`CAutoFight`（`AutoFight.cpp`）；
  状态机：`CChar::heart_beat` / `CharState.cpp`。

**Design Intent**（clarified）：
- **已确认（作者 2026-10-24）**：击晕归属 60 秒窗口 + 同门零经验 = 反抢怪设计；
  PK 不给经验 = PK 不以刷级为动机；死亡不掉技能 = 软死亡策略。
- **遗产约定（作者裁定，非本仓库刻意设计）**：战力公式的 `level³/3` 立方项与
  玩家经验半衰（`combat_exp > 10000 → 6000 + exp/2`）沿袭经典 MUD 谱系、按手感调校。
- 其余动机 `[inferred — confirm]`。

## 3. Detailed Design

### 3.1 Core Mechanics

**① 战斗容器与队伍轮换（CFightRoom）**
- **Description**：战斗不是角色 flag，而是一个按需 `load_item("fight_room")`
  创建的虚拟房间，双方 `move` 进入才开打。
- **Implementation**：`src\item\FightRoom.cpp`。每 2 心跳（`heart_beat` 的 `tick < 1`
  跳拍）：`advance_ap()` → `run_team_turn(turn % 2 ? 0 : 1)`（队伍奇偶轮换）。
  每队槽位 `MAXFIGHTERS=16`，实际参战上限 `m_fighters_max=4`（`create(1)` 时 8，
  `FightRoom.cpp:39,493`）。目标由 `select_member` 在敌队随机槽位选择。
  连续 3 拍选不到目标 → `end_fight()`；队内全员 AP 封顶 500。
- **Design Rationale**：`[inferred — confirm]` 以空间承载战斗，组队/观战/逃跑
  自然落在容器语义里（见概念文档 §6 技术认知）。
- **Player-Facing**：`kill`/`fight` 后被搬进战斗房间；`guard <房>` 观战、
  `join <房> <0|1>` 入队、`halt`（=flee，花 50 AP）退出。

**② 行动点（AP）经济**
- **Implementation**（`FightRoom.cpp:322-343, 515-525`）：
  - 每回合累积 `tp = query_turn_ap()/2`，其中 `query_turn_ap = max(dex, 2)`（busy 或
    非存活取 2）；**首回合翻倍**（即得满 dex）；busy 者不增长；累计 500 封顶（超量截断）。
  - 消耗：逃跑 50（`CmdStandardCombat.cpp:355-375`）；战斗中 `get/drop/give` 30、
    `use` 50、`wield/unwield` 25（`CmdHandle.cpp:51-68`）；施法 AP 见 ⑦。
- **Player-Facing**：敏捷决定出手节奏；战斗中做杂事要「花时间」。

**③ 攻击管线（12 阶段）** — `CAttack::execute`（`src\combat\Attack.cpp:25-66`）
1. `select_skill` — 依武器 `skill_type`，否则备用招式表（两套徒手准备时按
   `action_flag` 交替），否则 `unarmed`。
2. `retrieve_action` — 取该招式动作表（Lua `query_action` 返回
   `{action, dodge, parry, damage}` 四修正值）。
3. `validate_force` — 内功匹配（`valid_force`）；不匹配 ⇒ `damage_ratio /= 2; force_ratio = 0`
   （**惩罚而非拒绝**，`Attack.cpp:138-145`）。
4. `apply_ratio_rules` — Lua `attack_ratios` hook 可整体改写四修正值。
5. `build_action_description` — 展开 `$N/$n/$w/$W/$d/$P/$p/$l` 占位符。
6. `resolve_dodge` — 见 ④。
7. `resolve_parry` — 见 ⑤（已闪避则跳过；招架未中可被套装特效 `ParryMissed` 拦截）。
8. `calculate_damage` — 见 ⑥。
9. `replace_placeholders` → 10. `dispatch_message` → 11. `apply_weapon_effects`
   （招架命中的夺械/断械，`WeaponEffect.cpp:22-49`）→ 12. `send_verbose_debug`；
   之后 `set_effect` 的 `PostAttack` 阶段。
- **连击**：徒手且准备了 ≥2 套招式时，`CCombatd::fight` 追加一次 `TYPE_QUICK`
  （`Combatd.cpp:53-75`，文案前缀「紧跟着」）。

**④ 闪避**（`Attack.cpp:189-260`）
- `ap = skill_power(攻击方, 攻击位)`、`dp = skill_power(防守方, "dodge", 防守位)`，
  均下限 1；防守方 busy ⇒ `dp /= 3`。
- 修正：`dp ×(100 + mod)/100`，`mod = 招式 dodge 修正 + 防守方当前 dodge 动作修正`
  （`>1000000` 时先除后乘防溢出）。
- 骰子：`urandom(ap + dp) < dp` ⇒ 闪避 ⇒ `damage = RESULT_DODGE(-1)`。
  即 **P(闪避) = dp/(ap+dp)**。
- `TYPE_HIT` 强制 `dp = 1`（必中）。

**⑤ 招架**（`Attack.cpp:265-343`）— 武器矩阵：
| 防守方 | 攻击方持械 | 攻击方徒手 |
|---|---|---|
| 持械 | `pp = skill_power("parry")` | `pp = skill_power("parry") × 2` |
| 徒手 | `pp = 0`（**无法招架**） | `pp = skill_power("unarmed")` |
- busy ⇒ `pp /= 3`；骰子同闪避（`P = pp/(ap+pp)`）；招架成功 ⇒ `RESULT_PARRY(-2)`；
  未中 ⇒ `set_effect(ParryMissed)` 拦截或进伤害阶段；Lua `resolve_parry` 可改写结果。

**⑥ 伤害公式**（`Attack.cpp:348-478`，按执行顺序）
```
dmg  = (apply/damage 下限0) + query_skill(攻击类型)/4
dmg  = (dmg + random(dmg)) / 2                      -- ±50% 骰子
dmg  = dmg × (100 + damage_ratio) / 100             -- 招式修正
dmg  = dmg × (100 + level) / 100                    -- 等级放大
bonus = query_str() × (100 + force_ratio) / 100     -- force_ratio 受内功匹配门控
若 mp ≥ mp_factor 且 mp_factor ≠ 0 ⇒ 触发内功 hit_ob 注入 bonus
dmg  = dmg + (bonus + random(bonus)) / 2
-- 经验差减伤循环：
defense_factor = level2_exp(victim_level) + 1; my_exp = level2_exp(my_level)
while random(defense_factor) > my_exp:              -- RANDOM(x)=random(x)
    dmg -= dmg / 3;  defense_factor /= 2 (下限1)
dmg  ← Lua hook calculate_damage 可改写
victim.receive_damage("hp", dmg, me)
```
- **负伤（wound）**：`dmg > apply/armor` 且命中以下概率之一时额外
  `receive_wound` 削 `eff_hp`（**削上限**）：杀戮意图+持械 1/2、杀戮+徒手 1/4、
  非杀戮+持械 1/4、非杀戮+徒手 1/7（`Attack.cpp:445-455`）。

**⑦ 忙碌（busy）与中断**
- 互斥双模式：倒计时 `start_busy(n)`（每心跳 -1）或函数驱动 + `m_interrupt`。
- busy ⇒ 战斗房间内不行动、不累积 AP、防守 ÷3；多数指令先查 `is_busy()`，
  战斗中执行杂务再 `start_busy(2)`。

**⑧ 魔法（cast）**（`src\lua\LuaSkill.cpp:331-368`、`Skill.h:38-46`）
- AP 消耗 `= entry.ap × (120 − skill_base/4 − level/2) / 100`（下限 1），
  成功才 `resume_ap` 扣除；默认 `mp=10, ap=100, target=CAST_TO_RANDOM, hostile=1`。
- 冷却：`no_cast` temp + `call_out`（秒数由 Lua 返回）；房间 `no_cast`/busy 亦禁止。
- 敌意施法设 PK 标记（`ready_pk`）。

**⑨ 状态条件（毒等）**（`src\char\CharSkill.cpp:54-125`、`engine/Condition.h`）
- 脚本化条件：`init` 一次、`update_condition(me, duration)` 每心跳，
  返回 `CND_CONTINUE, duration-1` 续期（时长单位 = 心跳拍，约 5–9 秒）。
- `apply_condition`：被 `apply/poi_shield` 挡；同名更弱不覆盖；damage 钳制
  `[0,1000]`；施毒者记录在 `condition/who_<cnd>`。
- 中毒伤害：`receive_poison` ⇒ `damage × (poison技能/100 + 1)` 且附带负伤
  （`CharCombat.cpp:279-292`）。

**⑩ 昏迷/死亡/复活状态机**（`Char.cpp:115-130`、`CharState.cpp`）
```
存活 ──hp<0 且 IS_LIVING──▶ 昏迷（hp=0,mp=0, 禁言禁动）
        昏迷 ──m_revive = random(100 − con) + 30 拍──▶ 复活
存活 ──eff_hp < 0──────────▶ 死亡
死亡逃生舱（按序）：fb_nodie（副本免死）→ 救命金丹（kill/flee−kill/death>0，掉光装备）
        → 真死：death_times++、击杀者结算、尸体（PK 房不掉尸）
玩家 → start_city 复活（hp=1, eff_hp=max/2）；NPC → DESTRUCT（房间 reset 再刷新）
```
- **击杀经验归属**：`last_fainted_from` 匹配 + 60 秒归属窗（`CharCombat.cpp:74`）；
  同门击杀零经验；队友/同室同战队的师父朋友可共享归属（`CReward.cpp:182-237`）。

**⑪ 奖惩结算**（`src\combat\CReward.cpp`）
- NK（打怪）经验阶梯按受害者 `combat_exp`：35/50/75/99/150/195/255/300，
  单杀上限 `level×4+100`；队伍分摊 `times = (有效经验 − dx/2)/(dx+1)` 钳制
  `[0,2]`，`dx = cx×4/9`。
- PK（**已确认设计**）：击杀者经验收益恒 0（`CReward.cpp:337-340`）；受害方损失
  `10×exp_v/(exp_k+1)×(4000+exp_v)/1500`（杀手经验更高时）否则 `(4000+exp_v)/150`，
  钳制不超 `exp_v − sk_exp`；罪恶 `kill/guilt`（城市 +50/+10/+5、受害 −20，
  86400 秒洗白），城市杀人刷 `pub_guard`（1.5 倍杀人者经验）。
- 死亡损失：`(combat_exp − sk_exp)/160`；技能死亡惩罚 = **刻意空实现**
  （注释「当前策略为死亡不掉技能」），`skill_death_recover` 反而按
  `learned = (lv+1)²×3/4` 返还每项技能一级。
- PK 准入：双方等级均 ≥75；房间 `pk_protect = N` 保护等级 ≤N 的玩家。

**⑫ NPC 敌对 AI**（`src\combat\AutoFight.cpp`）
- 四型：`berserk/hatred/vendetta/aggressive`；启动延迟 `5 + random(5)` 拍
  （给受害者逃跑窗）；berserk 被 NPC 自身或 `mp > (random(shen)+shen)/10` 压制；
  `shen > score` 决定 kill vs spar。Wimpy：`hp×100/max_hp ≤ env/wimpy` 自动 `halt`。

## 5. Edge Cases

**Handled in Code**：
- ✅ 比例缩放整数溢出：`dp > 1000000` 时改序为 `dp/100×(100+mod)`（`Attack.cpp:223-226`）。
- ✅ `TYPE_HIT` 必中：强制 `dp=1`、`pp=1`。
- ✅ 攻击中途武器消失：首击后重新 `query_weapon`；连击仅徒手触发（`Combatd.cpp:62-69`）。
- ✅ 错配内功：半伤 + force 归零，**不拒绝出招**。
- ✅ 套装特效可在 `ParryMissed` 阶段整体吞掉伤害（`SetEffect.cpp:51-72`）。
- ✅ 宠物伤害/负伤/击杀归属挂到主人（`CharCombat.cpp:47-56,100-104`）。
- ✅ 抢怪保护：击晕归属 60 秒窗 + 同门零经验 + 归属匹配才发击杀经验。
- ✅ 野兽动词白名单：未知动词抛 Lua 错，防止静默退化为 0 伤害默认攻击
  （`CharFight.cpp:421-445`）。
- ✅ 投掷武器耗尽播报后递减；`owner`/`no_duo` 武器不消耗（`WeaponEffect.cpp:58-70`）。
- ✅ 条件覆盖：更弱的同名毒不覆盖、伤害钳 `[0,1000]`、脚本缺失/损坏拒绝施加。
- ✅ `receive_damage` 钳至 −1、仅接受 hp/mp；心跳按阈值重推导昏迷/死亡。
- ✅ 组队自动拉跟随者入战（`FightRoom.cpp:436-472`）；net-dead 不可被选为目标。

**Not Yet Handled**（discovered during analysis）：
- ⚠️ `Attack.cpp:418` 对 `unsigned long my_exp` 判断 `< 0` —— 恒假，死代码
  （防御循环的下限保护实际不生效，靠 `defense_factor ≥ 1` 兜底）。
- ⚠️ `CReward.cpp:337-340` PK 零经验以「算后清零」表达，意图不可读（见 §4）。

**Unclear**（need user clarification）：
- ❓ `CReward` 的 PK 损失公式在「杀手经验更低」分支给受害方 `(4000+exp_v)/150`
  损失——低等级被高等级 PK 与被同级 PK 的损失差是否有意为之？`[inferred — confirm]`
- ❓ `resolve_parry` Lua hook 允许在招架判定后直接改写伤害——该权威是否应
  与 `calculate_damage` 合并？（两个 hook 都能改伤害，脚本作者易混淆）`[inferred — confirm]`

**Balance Concerns Identified**：
- ⚠️ **经验差减伤循环是乘性叠加在等级放大之上**：跨级战斗可能呈现「完全打不动」；
  这是 legacy 曲线的自然结果，PK 门槛（75 级）挡住了大多数受害场景，但副本内
  跨级组队（低级蹭高级房）体验值得实测。
- ⚠️ **教学占位数值污染直觉**：`lua-sample` 的 10000/杀、+100000 果实会让人把
  示例节奏误当设计节奏；数值策划请以 `level_exp.lua` + `kill_bonus` 默认值为基线。
- ⚠️ **徒手双招连击免费多一击**（阶段 ③ 连击不耗 AP），持械玩家的等价收益
  来自武器 `apply` 与招架优势——两条路线的 DPS 平衡未见成文依据 `[inferred — confirm]`。

**Recommended Balance Pass**：
- 用 `/balance-check` 扫 §4 #1/#6/#8 三条曲线在 1–176 级区间的表现。
- 实测场景：75 级 PK 门槛两侧、副本内跨级组队、徒手连击 vs 持械 sustained DPS。
